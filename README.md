# ROZLF AUTO TRADER

لوحة ROZLF عربية/إنجليزية، مهيأة للآيفون، لقراءة بيانات حساب ExpertOption وتحليلها. الوضع الحالي **قراءة وتحليل فقط**؛ لا يرسل أوامر شراء أو بيع ولا يضمن الأرباح.

## الوضع الحالي

- واجهة فاتحة بهوية ROZLF، أزرق أساسي، فيروزي للإيجابي وأحمر للسلبي، مع تخطيط متجاوب وتنقل سفلي.
- لا يوجد تسجيل دخول تقليدي أو مفتاح لوحة. الوصول الخاص يتم عبر ربط Telegram: اكتب `/connect` في بوت ROZLF، وافتح الرابط المؤقت لإدخال Session Token في صفحة HTTPS آمنة.
- ExpertOption: الجلسة تُحفظ مشفّرة باستخدام `APP_SECRET_KEY`، ثم لا تُعتبر متصلة إلا بعد تحقق الجسر من الحساب فعلياً.
- جسر ExpertOption المحلي يعمل داخل خدمة Node على `127.0.0.1:8011` عند عدم ضبط جسر خارجي. لا حاجة لخدمة Render ثانية عند استخدام هذا الوضع.
- الأصول تُقرأ من قائمة الحساب الحقيقية. لا تظهر أصول Smarty أو OTC على أنها متاحة إلا إذا طابقت اسماً/رمزاً في قائمة الحساب الحية.
- كل البيانات تمر عبر طبقة مصادر موحّدة للقراءة فقط (`eo_bridge/sources/`) بلا أي دالة تنفيذ؛ التفاصيل في [docs/DATA-SOURCES.md](docs/DATA-SOURCES.md).
- `GET /api/expertoption/verify` يفحص كل أصل مطلوب (مدرج، هوية، سعر، شموع، سلامة، حداثة، فريمات، اتصال) ويُرجع تقريراً صريحاً بدل اعتبار الأصل «متاحاً» بلا دليل.
- التحليل يعتمد على الشموع التي يعيدها الجسر، ومؤشرات RSI/MACD/EMA/ADX وقراءة بنية السوق. البيانات القديمة أو الناقصة أو الأصل/المدة غير المدعومين تعطي `NO TRADE`.
- قد يراجع Mistral الإشارة عند ضبط `MISTRAL_API_KEY`. غياب المفتاح يعني تحليل قواعد فنية فقط.
- MT5 مخفي ومعطّل في واجهة المنتج حالياً، ويمكن إعادة تقييمه لاحقاً.
- Telegram اختياري ويتطلب `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`.

## مفاتيح مهمة

| المتغير | الغرض |
| --- | --- |
| `APP_SECRET_KEY` | مفتاح ثابت لتشفير جلسة ExpertOption. لا تغيّره بعد حفظ الجلسة إلا مع خطة تدوير مفاتيح. |
| `PUBLIC_APP_URL` | رابط موقع ROZLF المستخدم في رابط الربط المؤقت من Telegram. |
| `TELEGRAM_BOT_USERNAME` | اسم بوت Telegram بدون @ (اختياري لزر فتح البوت). |
| `DATABASE_URL` | PostgreSQL دائم لحفظ الجلسة المشفّرة والإعدادات بين عمليات النشر. |
| `EXPERTOPTION_BRIDGE_URL` | اختياري؛ عند تركه فارغاً يستخدم التطبيق الجسر المحلي. |
| `EXPERTOPTION_BRIDGE_KEY` | مفتاح مشترك للجسر الخارجي؛ في الجسر المحلي يُمرّر المفتاح داخلياً. |
| `EXPERTOPTION_RESTORE_SESSION` | يفعّل استعادة الجلسة المشفّرة بعد إعادة تشغيل الخدمة. |
| `EXPERTOPTION_ALLOW_REAL_READ` | يسمح بقراءة حساب حقيقي فقط، ولا يفعّل تنفيذ الصفقات. |
| `MISTRAL_API_KEY` | مراجعة الذكاء الاصطناعي الاختيارية. |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | إشعارات Telegram الاختيارية. |

لا تضع أي Session Token أو API Key في GitHub أو في ملفات الواجهة. لا ترسل Session Token إلى المحادثات. اكتب `/connect` في البوت المصرح به؛ يصدر رابط HTTPS عشوائياً صالحاً لخمس دقائق ولمرة واحدة. أدخل الجلسة في الصفحة، وبعد التحقق ينشئ الخادم ملف ارتباط HttpOnly موقّعاً لمدة 30 يوماً.

## الفرق بين المفتاحين

1. **ربط Telegram:** اكتب `/connect` في محادثة البوت المصرح بها، ثم افتح رابط الربط المؤقت وأدخل Session Token هناك. لا ترسل التوكن كرسالة.
2. **ExpertOption Session Token:** يُدخل داخل صفحة الربط الآمنة التي يفتحها زر البوت؛ لا يُرسل في رسالة Telegram ولا يظهر في واجهة لوحة التحكم.

يمكن لصندوق ExpertOption قبول قيمة `token` وحدها أو سلسلة Cookies كاملة تحتوي `token=`؛ الخادم يستخرج قيمة `token` فقط ولا يمرر بقية ملفات الارتباط إلى الجسر.

## تشغيل محلي

يتطلب Node.js 20+ وPython 3:

```bash
npm install
cp .env.example .env
npm start
```

افتح `http://localhost:8000`. افحص حالة الخدمة من:

```text
GET /api/health
```

تشغيل اختبارات Python:

```bash
python3 -m pytest -q
```

اختبارات JavaScript:

```bash
npm test
```

## تحقق الاتصال والإشارات

- `/api/health` يثبت أن خدمة ROZLF والجسر يعملان؛ لا يثبت وحده أن حساب ExpertOption متصل.
- الجلسة تعتبر حقيقية فقط عندما تكون `verified: true` ويعيد الجسر سجل الحساب.
- الإشارة لا تعتبر مبنية على بيانات الحساب إلا عندما تكون `data_verified: true` والشموع حديثة وكافية.
- `BUY` و`SELL` ليستا ضماناً للربح أو نسبة نجاح إحصائية. لا توجد دقة مضمونة، ولا ينبغي تحويل درجة القوة إلى احتمال ربح.
- لا يمكن تأكيد توفر Smarty أو OTC أو أي مدة قبل قراءة قائمة الحساب والشموع الفعلية.

## المتصفح السحابي (Cloud Connector) — الربط من الآيفون بدون حاسوب

تبويب **متصفح سحابي** هو المسار الأول في قسم جلسة ExpertOption. يعمل بتشغيل Chromium معزول على الخادم نفسه، وتُعرض شاشته داخل ROZLF كصور JPEG متجددة، وتُرسل لمساتك وكتابتك إلى ذلك المتصفح عبر CDP.

1. اضغط **تشغيل المتصفح السحابي** — يبدأ Chromium بملف تعريف مؤقت داخل `/tmp` (لا يستخدم أي جلسة محفوظة).
2. تُعرض صفحة `m.expertoption.com` داخل الصفحة. سجّل الدخول بنفسك: كلمة المرور تُكتب داخل المتصفح المعزول فقط، ولا تمرّ عبر واجهة ROZLF ولا تُسجَّل في السجلات ولا في قاعدة البيانات.
3. كل 1.5 ثانية يقرأ الخادم `document.cookie` و`localStorage` داخل تلك الصفحة لالتقاط رمز الجلسة.
4. عند التقاط الرمز يُرسل إلى محرك ROZLF (متغيّر `EXPERTOPTION_BRIDGE_URL` / الموصّل المحلي)، ويُختبر مع ExpertOption فعلياً. **لا تظهر حالة «متصل» إلا إذا كان `verified: true`.**
5. عند النجاح أو الفشل أو انتهاء 10 دقائق تُغلق نافذة Chromium ويُحذف ملف التعريف المؤقت، فلا تبقى جلسة محفوظة على الخادم.

نقاط النهاية (كلها خلف بوابة المصادقة `DASHBOARD_TOKEN`/جلسة المالك):

| المسار | الوظيفة |
| --- | --- |
| `GET /api/cloud-connector/status` | الحالة، الرابط الحالي، توفّر Chromium، الخطأ الأخير |
| `POST /api/cloud-connector/start` | بدء جلسة معزولة (حد 6 طلبات/دقيقة) |
| `GET /api/cloud-connector/frame` | صورة JPEG حيّة للشاشة (بلا تخزين مؤقت) |
| `POST /api/cloud-connector/input` | `click` / `scroll` / `text` / `key` / `navigate` (التنقل داخل expertoption.com فقط) |
| `POST /api/cloud-connector/stop` | إنهاء فوري وحذف ملف التعريف |

المتغيرات: `CLOUD_CONNECTOR_ENABLED` (افتراضي `true`)، `CLOUD_CONNECTOR_TTL_MS` (افتراضي 600000)، `CLOUD_CONNECTOR_LOGIN_URL`، و`CHROMIUM_PATH` إن وُجد متصفح نظامي.

قيود تشغيلية يجب معرفتها:

- يُستخدم `@sparticuz/chromium` (نسخة Headless Chromium مضغوطة) لأن بيئة Render لا توفر متصفحاً نظامياً. تحتاج الذاكرة إلى **1GB على الأقل**؛ خطة Render المجانية (512MB) قد تفشل عند فتح الصفحة أو أثناء التحليل.
- البث هنا **صور JPEG كل ~0.4 ثانية** وليس فيديو WebRTC؛ هذا يقلل استهلاك المعالج والذاكرة ولا يحتاج خدمة إضافية.
- إذا كان `CLOUD_CONNECTOR_ENABLED=false` أو تعذّر تشغيل Chromium، تعرض الواجهة السبب الحقيقي ولا تدّعي أي اتصال.
- الجلسة الناتجة للقراءة والتحليل فقط: `ENABLE_REAL_TRADING=false` و`execution_enabled: false` دائماً.


### فحص قدرات الخادم (Host Probe) — رقم فعلي لا افتراض

عند كل تشغيل للخدمة (بعد ٢٠ ثانية) يفتح ROZLF متصفحاً معزولاً على **الخادم نفسه** ويقوم بالتالي:
تشغيل Chromium وقياس زمن الإقلاع، فتح صفحة ExpertOption، التقاط صور JPEG للشاشة،
إرسال لمسة/تمرير وكتابة نص، ثم قياس **أعلى استهلاك للذاكرة** (RSS و PSS) للعملية ومجموعتها
مقارنة بحد الذاكرة في الحاوية، ثم إغلاق المتصفح وحذف ملفه المؤقت.

نتيجة الفحص تظهر في `GET /api/public/status` داخل `cloud_connector` وتُعرض في لوحة
«المتصفح السحابي» كثلاثة أسطر منفصلة:

1. تشغيل المتصفح على الخادم (نجاح إقلاع Chromium فقط).
2. بث صور الشاشة وإرسال اللمسات (نجاح الالتقاط والتحكم).
3. اتصال حقيقي بحساب ExpertOption — يبقى «غير متصل» حتى تسجّل الدخول بنفسك.

أي أن نجاح المتصفح **لا يعني** نجاح الاتصال بالحساب. تُضاف أيضاً قيمة استهلاك الذاكرة
`peak_rss_mb` / `peak_pss_mb` و`limit_mb` و`server_rss_mb`.

لتعطيل الفحص: `CLOUD_CONNECTOR_PROBE=false`.
الحماية من حلقات إعادة التشغيل: تُسجَّل حالة الفحص قبل الإقلاع؛ فإذا أعاد Render تشغيل
الخدمة أثناء الفحص يُكتشف ذلك في التشغيل التالي ويُتخطى الفحص مرة واحدة.

## ربط الجلسة عبر Safari / الموصّل المحلي

هذا هو مسار الربط الافتراضي في الواجهة، ولا يحتاج أي إدخال يدوي للتوكن في الموقع أو في Telegram.

1. افتح ROZLF، ثم قسم **جلسة ExpertOption** ← تبويب **ربط عبر Safari**.
2. اضغط **إنشاء رمز الربط**. يظهر رمز مثل `ABCD-2345` صالح 10 دقائق ويُستهلك مرة واحدة.
3. شغّل الموصّل على جهازك:

```bash
pip install -r connector/requirements.txt
playwright install chromium        # مرة واحدة
python connector/rozlf_connect.py --app https://rozlf-auto-triding-1.onrender.com --code ABCD-2345
```

4. تُفتح نافذة متصفح مستقلة على `m.expertoption.com`؛ سجّل الدخول بحسابك التجريبي داخلها.
5. يقرأ الموصّل رمز الجلسة من نافذته، يشفّره على جهازك بـ PBKDF2-SHA256 + AES-GCM بمفتاح مشتق من رمز الربط، ويرسل **النص المشفّر فقط** إلى `/api/connect/session`.
6. يفك الخادم التشفير بمفتاح `APP_SECRET_KEY`، يحفظ الجلسة مشفّرة، ثم يختبرها فعلياً. لا يظهر «متصل» إلا إذا كانت `verified: true`.

بديل عند تعذّر المتصفح: `--paste` للصق قيمة `token` يدوياً (لا تظهر على الشاشة).

قيود يجب معرفتها:

- على iPhone/iPad لا يستطيع أي موقع قراءة جلسة موقع آخر، لذلك **يجب** تشغيل الموصّل على حاسوب؛ الرمز يُنشأ من الجوال والموصل يعمل على الكمبيوتر.
- ROZLF لا يقرأ ملفات cookies في متصفحك ولا يطلب كلمة مرورك؛ الموصّل هو من يفتح نافذته الخاصة.
- إذا فشل التحقق بعد وصول الجلسة، تعرض الواجهة سبب الفشل الحقيقي (مثل: لا يوجد endpoint أكمل مصافحة) ولا تدّعي النجاح.
- `APP_SECRET_KEY` يجب أن يبقى ثابتاً على Render وإلا تعذّر فك تشفير الجلسات المحفوظة.

## النشر على Render

إعداد الخدمة الحالية في `render.yaml` يستخدم خدمة Node واحدة. الجسر المحلي مضمّن في المستودع ويُشغّل بجانبها. احتفظ بمتغيرات البيئة التالية على Render:

- `APP_SECRET_KEY`
- `PUBLIC_APP_URL`
- `DATABASE_URL`
- `EXPERTOPTION_RESTORE_SESSION=true`
- `EXPERTOPTION_ALLOW_REAL_READ=true` عند الحاجة لقراءة حساب حقيقي
- `MISTRAL_API_KEY` (اختياري)
- `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` (اختياريان)

تأكد أن `APP_SECRET_KEY` لا يتغير بين عمليات النشر. خطة Render المجانية قد تدخل في وضع السكون ولا تضمن عملاً متواصلاً 24/7.

## الأمان والقيود

- لا توجد واجهة تداول عامة موثقة ومصرح بها من ExpertOption في هذا المشروع؛ التكامل الحالي قراءة بيانات وتحليل فقط عبر جسر غير رسمي، وقد يتوقف إذا غيّرت المنصة بروتوكولها أو رفضت الجلسة.
- لا يوجد تنفيذ صفقات ExpertOption. أي زر أو شاشة يجب ألا تدّعي إرسال أمر تداول.
- لا تستخدم الجلسة التي سبق نشرها في محادثة أو سجل؛ ألغها من ExpertOption وأنشئ جلسة جديدة.
- لا توجد إشارات مضمونة ولا ضمان لعائد مالي.
